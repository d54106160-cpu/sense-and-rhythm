# 感官與節奏挑戰 — 規格書

**作品名稱**：感官與節奏挑戰

> 用 Vibe Coding 做出的互動網頁，單一 `index.html`（CSS 與 JavaScript 皆寫在檔案內），透過 GitHub Pages 公開。

## 1. 發想與目標

- **創作動機**：將生活中對角度、色彩、水平與節奏的主觀感知，轉化為能回饋結果的趣味互動挑戰。
- **作品內容**：四個小遊戲 ── 角度直覺、色彩記憶、水平大師、節奏鼓手。
- **回饋方式**：每題作答後立即給分，並指出誤差的方向與大小（例如角度差幾度、顏色哪個通道偏多、哪一邊偏低、搶拍或拖拍幾毫秒）。
- **使用對象**：想挑戰自己目測與記憶準確度的人；想跟著節拍器練習基本功的爵士鼓初學者。
- **操作平台**：電腦（鍵盤 / 滑鼠）與手機（觸控）皆可操作。
- **題數**：每個遊戲**無限題數**，一題一題練習。

## 2. 整體設計

| 項目 | 規格 |
|---|---|
| 檔案 | 單一 `index.html`（HTML + CSS + JS） |
| 頁面結構 | 首頁（四個遊戲卡片）＋四個遊戲頁，用網址 `#angle` `#color` `#level` `#drum` 切換，瀏覽器返回鍵可用 |
| 視覺風格 | 前三個遊戲：簡約、米白底、柔和綠／橘色；節奏鼓手：深色霓虹風（青色＝左手、桃紅＝右手） |
| 成績紀錄 | 每個遊戲記錄「已玩題數、平均分、最佳分」，存在瀏覽器 localStorage |
| 評語 | ≥95 神準／≥85 非常好／≥70 不錯喔／≥50 再接再厲／其餘 多練習幾次 |

## 3. 遊戲規格

### 遊戲一：角度直覺
- **題目**：隨機給定 10°～350° 的整數角度
- **操作**：長按「按住張開」按鈕（或空白鍵），第二條線以每秒 60° 逆時針張開；**放開即停止並送出**
- **畫面**：兩條線從頂點張開，中間以淺色扇形顯示角度；作答中不顯示目前度數
- **結果**：顯示實際角度、誤差，並用橘色虛線標出正確位置
- **計分**：`100 − 誤差° × 3`（最低 0 分）

### 遊戲二：色彩記憶
- **題目**：隨機產生一個顏色（避免過暗或過灰）
- **流程**：記住顏色 → 按「記住了！」→ 題目消失 → 拖動 **R / G / B 三條滑桿**（0–255）憑記憶調色 → 按「確定」
- **滑桿**：每條滑桿的底色會即時顯示「只改變這個通道」時的顏色變化，幫助理解 RGB 混色
- **結果**：題目與作答顏色並排、顯示 RGB 數值，並提示紅、綠、藍各多或少了多少
- **計分**：RGB 空間距離 d（0–441），`100 × (1 − d / 300)`（最低 0 分）

### 遊戲三：水平大師
- **情境**（可切換）：
  - 🖼️ 牆上掛畫：畫框掛在釘子上歪掉；8 種畫作、4 種畫框，尺寸與直橫比例隨機
  - 📷 相機取景：方形觀景窗（有 REC 等相機資訊），5 張風景輪流出現（海景、城市、湖景倒影、田野、夜海）
- **防止對照**：掛畫的牆面是隨機的不規則形狀，干擾物都是生活中本來就不水平的東西：斜向壁紙紋路、斜射的陽光、自然下垂的串燈、隨手斜貼的便利貼、牆面裂痕；相機畫面加上斜向的鏡頭光斑
- **題目**：隨機歪斜 ±3°～18°
- **操作**：`←` 抬高左邊、`→` 抬高右邊（或畫面上的按鈕）；點一下微調 0.2°，按住 0.25 秒後連續旋轉；`Enter` 或「完成」送出
- **結果**：顯示還差幾度、哪一邊偏低，並用虛線標出真正的水平位置、提示該按哪個方向鍵
- **計分**：`100 − 誤差° × 15`（最低 0 分）

### 遊戲四：節奏鼓手（節拍器）
- **模式**（可切換）：
  - **基本**：每一格都要打
  - **進階（含空拍）**：只練「一拍四下」與「三連音」兩種型態。每題抽一組固定的空拍規律，整題每一拍都重複同一組，標示「空」的地方不要打
    - 一拍四下：以「右左右左」四格為一組，挖掉 1～3 格（至少保留一下），共 14 種，例如：空左右左、右空右左、右左空左、右左右空、空空右左、右空空左、右空空空、空空空左…
    - 三連音：以「右左右」三格挖掉 1～2 格；因為三連音的手順每拍左右互換，畫面以兩拍為一組顯示（例如 空左右空右左 ×2）
- **題目**：每題隨機抽選 BPM 與節奏型態

  | 型態 | 手順（爵士鼓習慣由右手開始） | BPM 範圍 |
  |---|---|---|
  | 一拍一下（四分音符） | 右 左 右 左 | 60–140 |
  | 一拍兩下（八分音符） | 右左 右左 右左 右左 | 60–120 |
  | 一拍三下（三連音） | 右左右 左右左 … | 60–100 |
  | 一拍四下（十六分音符） | 右左右左 … | 60–90 |

  手順依照格子位置交替，進階模式的空拍也佔一格（所以「右 空 右 左」中，空拍原本是左手的位置）
- **流程**：按「開始」（或空白鍵）→ 預備 4 拍 → 在下一聲「嗒」打下第一下，跟著節拍器打 4 小節
- **對拍規則**：每一拍的第一格（畫面上以 ♩ 標示）要和節拍器聲同時打
- **操作**：左手 `F`、右手 `J`；手機點小鼓的左半邊（左手）或右半邊（右手）
- **畫面**：一個小鼓搭配兩支鼓棒，打擊時對應的鼓棒會落下並發光；4 顆拍點燈（第一拍為重音）；整小節的手順提示，目前位置會亮起；每一下即時顯示判定
- **判定**：Perfect ≤45ms（100 分）／Great ≤85ms（90 分）／Good ≤130ms（70 分）／Bad（40 分）；沒打到為 Miss；打錯手為「手順錯」（該音符分數 ×0.6）；多打一下扣 1 分，進階模式在空拍誤打一下扣 3 分
- **結果**：總分、各判定數量，以及「平均偏早或偏晚多少 ms（搶拍／拖拍傾向）」與穩定度
- **技術**：使用 Web Audio API 精準排程節拍聲，並補償音訊輸出延遲

## 4. 使用技術
- HTML / CSS / JavaScript（無外部框架）
- SVG：角度、掛畫、相機畫面、小鼓與鼓棒
- range 滑桿：RGB 調色
- Web Audio API：節拍器與鼓聲
- Pointer Events：同時支援滑鼠與觸控長按
- localStorage：保存成績

## 5. 開發過程（Vibe Coding）
1. 提出四個小遊戲的想法
2. 與 AI 討論細節：視覺風格、調色方式、水平情境、節拍器玩法、題數、手機支援、按鍵配置、BPM 設定
3. 整理成本規格書
4. 由 AI 依規格產生 `index.html`
5. 實際試玩後調整（第一輪）：放寬鼓點判定、明確標示對拍位置、鼓面改成小鼓與鼓棒；水平遊戲移除可對照的方框，加入干擾圖形與更多畫作與風景
6. 第二輪調整：相機改為方形觀景窗、方向鍵改為「按哪邊抬哪邊」、調色改用 RGB 滑桿並放寬給分、鼓改為一個小鼓、手順改為右手開始、新增進階空拍模式、移除不合理的歪斜層架
7. 第三輪調整：進階空拍改為固定規律（每題一組，整題重複），並加入只打一下的組合（右空空空、空空空左等）；進階模式只練一拍四下與三連音
8. 上傳 GitHub 並用 GitHub Pages 公開
